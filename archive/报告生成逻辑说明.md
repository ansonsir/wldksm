# ScanScript 报告生成逻辑说明

## 1. 概述

本项目采用"一个扫描任务一份报告"的粒度，报告格式为 Word 文档（.docx），通过 `docxtpl` 库基于模板渲染生成。报告内容包含扫描概况、端口分类统计、设备详情和结论等模块。

## 2. 报告生成入口

报告生成有两个入口函数：

### 2.1 `generate_report()` —— 通用入口
位于 `core/report.py`，直接指定模板文件路径生成报告。

### 2.2 `generate_report_with_db()` —— 数据库配置入口
位于 `core/report.py`，通过 `TemplateManager` 自动从数据库或文件系统查找对应区域的模板，再调用 `generate_report()`。

**实际调用位置**：`web/app.py` 的 `scan_worker()` 中，扫描完成后自动触发：

```python
scan_data = {
    "scan_start_time": orchestrator.statistics.to_dict()['start_time'],
    "scan_end_time": orchestrator.statistics.to_dict()['end_time'],
    "scan_duration": orchestrator.statistics.to_dict()['duration'],
    "ip_range": "\n".join(ip_ranges[:8]) + (f"\n... (共{len(ip_ranges)}个网段)" if len(ip_ranges) > 8 else ""),
    "ports": ports,
}

report_success = generate_report_with_db(
    scan_data=scan_data,
    result_file=config.save_result_file,
    output_file=str(output_path),
    area_name=area_name,
    template_dir=config.template_dir,
    db_manager=db_manager,
    record_id=record_id,
)
```

## 3. 数据输入 (scan_data)

| 字段 | 说明 | 示例 |
|------|------|------|
| `scan_start_time` | 扫描开始时间 | `2026-04-23 17:10:06` |
| `scan_end_time` | 扫描结束时间 | `2026-04-23 17:10:14` |
| `scan_duration` | 扫描总耗时（格式化后的字符串） | `8秒` |
| `ip_range` | 扫描的网段列表（前8个+省略提示） | `10.0.0.0/24\n10.0.1.0/24\n...` |
| `ports` | 扫描端口列表 | `21,22,23,445,8080...` |

## 4. 数据分析流程 (ReportDataAnalyzer)

### 4.1 扫描结果加载
从 `scan_results.txt` 按行解析，每行格式为：
```
IP地址  [端口1, 端口2, ...]
```
示例：
```
10.0.0.13  [8443]
10.0.1.20  [445, 8080]
```

解析后生成 `DeviceInfo` 对象列表，每个对象包含 IP 和端口列表。

### 4.2 端口服务类别识别
`DeviceInfo.__post_init__()` 根据开放端口自动识别服务类别：

| 类别 | 识别端口 | 说明 |
|------|----------|------|
| FTP | 21 | 文件传输协议 |
| SSH | 22 | 安全 shell |
| RDP | 3389 | 远程桌面 |
| Database | 1433, 1521, 2181, 3306, 5432, 6379, 15672, 27017 | 数据库相关 |
| MQTT | 1883, 5672, 8161, 61616 | 消息队列/中间件 |
| SMB | 445 | 文件共享 |

### 4.3 红区判断（可选）
当启用红区扫描时，通过 `redarea_ips.txt` 中配置的网段，判断设备 IP 是否落在红区网段内。

红区设备格式：`IP {端口1, 端口2, ...}`

## 5. 模板字段列表

报告模板（.docx）中可使用以下占位符，渲染时会替换为实际数据：

### 5.1 基础信息字段

| 占位符 | 说明 |
|--------|------|
| `{{report_date}}` | 报告生成日期（`YYYY.MM.DD` 格式） |
| `{{scan_start_time}}` | 扫描开始时间 |
| `{{scan_end_time}}` | 扫描结束时间 |
| `{{scan_duration}}` | 扫描耗时 |
| `{{ip_range}}` | 扫描网段 |
| `{{ports}}` | 扫描端口 |

### 5.2 概况字段

| 占位符 | 说明 |
|--------|------|
| `{{p_overview}}` | 扫描概况文本（时间/耗时/目标/端口） |
| `{{p_summary}}` | 分类摘要统计（各端口类别设备数汇总） |
| `{{p_conclusion}}` | 结论（预留，当前为空） |
| `{{total_devices_num}}` | 检测到高危端口的设备总数 |

### 5.3 分类统计字段

每个类别包含两个字段：`数量字段` 和 `设备列表字段`。

| 类别 | 数量字段 | 设备列表字段 | 无数据时显示 |
|------|----------|--------------|-------------|
| FTP (21端口) | `{{p_ftp_devices_num}}` | `{{p_ftp_devices_info}}` | `没有设备` |
| SSH (22端口) | `{{p_ssh_devices_num}}` | `{{p_ssh_devices_info}}` | `没有设备` |
| RDP (3389端口) | `{{p_rdp_devices_num}}` | `{{p_rdp_devices_info}}` | `没有设备` |
| 数据库 | `{{p_db_devices_num}}` | `{{p_db_devices_info}}` | `没有设备` |
| MQTT | `{{p_mqtt_devices_num}}` | `{{p_mqtt_devices_info}}` | `没有设备` |
| 红区 | `{{p_redArea_devices_num}}` | `{{p_redArea_devices_info}}` | `没有设备` |

**数量字段格式**：
- 有数据：`共检测到N台设备`
- 无数据：`没有设备`

**设备列表字段格式**：
- 普通区（FTP/SSH/RDP/Database/MQTT）：每行一个 IP 地址，末尾换行
- 红区：`IP {端口1, 端口2, ...}`，每行一个设备

### 5.4 p_summary 文本示例

```
一共检测到39台设备存在高危端口开放，其中
21端口：共检测到3台设备
22端口：没有设备
3389端口：共检测到5台设备
数据库端口：共检测到8台设备
信息传输（MQTT等）：没有设备
红区：共检测到12台设备
```

### 5.5 p_overview 文本示例

```
本次网络高危端口扫描概况如下：
检测时间：2026-04-23 17:10:06
完成时间：2026-04-23 17:10:14
总耗时：8秒
扫描目标：
    网段：
    10.0.0.0/24
    10.0.1.0/24
    ... (共30个网段)
端口：
    21, 22, 23, 445, 873, 1433, 1521, 1883,
    2181, 2375, 3306, 3389, 5236, 5432, ...
```

## 6. Word 报告生成 (docxtpl)

使用 `docxtpl.DocxTemplate` 渲染模板：

1. 加载 `.docx` 模板文件
2. 将上述所有字段构建为字典
3. 调用 `docx.render(fields)` 替换占位符
4. 保存为输出文件

## 7. 文本报告生成

同时生成一份 `.txt` 格式的纯文本报告，结构与 Word 报告一致，便于日志查看和快速预览。

## 8. 模板选择逻辑

`TemplateManager.get_template_for_area()` 按以下优先级查找模板：

1. **数据库区域关联模板**：查找 `report_templates` 表中与当前扫描区域关联的活跃模板
2. **数据库全局模板**：查找任意活跃模板
3. **文件系统默认模板**：`data/templates/default.docx`
4. **文件系统任意模板**：目录下任意 `.docx` 文件

## 9. 完整数据流

```
扫描完成
  ↓
解析 scan_results.txt → DeviceInfo 列表
  ↓
端口分类识别 → 按 FTP/SSH/RDP/Database/MQTT 归类
  ↓
红区判断（如启用）→ 识别红区设备
  ↓
构建模板字段字典（scan_data + analysis_result）
  ↓
查找模板（数据库 → 文件系统回退）
  ↓
docxtpl 渲染 Word 报告
  ↓
保存到 data/reports/YYYY.MM.DD_网络高危端口扫描报告.docx
  ↓
更新 scan_records.report_file 字段
```

## 10. 报告命名规则

输出文件名格式：
```
{YYYY.MM.DD}网络高危端口扫描报告.docx
```

如果文件已存在，自动添加序号：
```
{YYYY.MM.DD}_1网络高危端口扫描报告.docx
{YYYY.MM.DD}_2网络高危端口扫描报告.docx
...
```
